# design/ · 规划与设计稿

这个目录放**还没实现的规划与设计稿**，用于开工前对齐方案。

与 `docs/` 的分工：

| 目录 | 内容 | 纪律 |
|---|---|---|
| `docs/` | 01 需求 / 02 详细设计 / 03 数据库部署 / 04 增补建议 / 05 接口清单 / 06 错误码 | **只写已实现的东西**。代码改了才改它 |
| `design/` | 规划稿、设计稿、可行性验证、选型对比 | 可以写「打算怎么做」，**不代表已经做了** |

判断标准很简单：写进 `docs/` 的必须是能在代码里找到对应实现的；`design/` 允许只是想法。

## 开工前必读的两条硬约束

### 1. Flyway 迁移版本号不能乱跳

Flyway 默认 `outOfOrder=false`，**不允许先跑 V15 再补 V12**。当前已用到 **V11**。三份文档里出现过的编号：

| 模块 | 文档里写的版本 | 说明 |
|---|---|---|
| 短剧库 · 文字层（6 张表） | V12 | 一期 |
| 短剧库 · 视觉层（6 张表 + alter） | V13 | 二期 |
| 本地模型服务（`t_local_grant` 等） | V12（拟） | **与短剧库文字层冲突** |

如果本地模型服务和短剧库都要做，必须重新排号再动手，否则线上迁移会直接失败。排号前先确认 `src/main/resources/db/migration/postgresql/` 里的实际最新版本。

### 2. 错误码分段不许重叠

| 段 | 归属 |
|---|---|
| 40088 ~ 40109 | 短剧库（文字层 40088~40095，视觉层 40096~40109） |
| 40200 ~ 40219 | 本地模型服务（40213 = 许可不允许商用） |

现有代码最大是 `40087`。新增错误码前先查 `docs/06-错误码.md`，避免撞号。

## 回家开发的第一件事

1.2 万字的需求不等于能直接写代码。建议顺序：

1. 打通 **V12 迁移**（短剧库 6 张表），`mvn flyway:info` 确认版本
2. 第一步只做**文字层**的分镜生成——视觉层每镜的输入（景别 / 时长 / 动作 / 台词）全部来自文字层，文字层不落地，视觉层只能拿假数据跑
3. 事实层回填排在这之前（线上 174 章只有 1 章有 `fact_summary`，不补的话分集大纲会缺料）
