> 版本：v1.0
> 日期：2026-11-10
> 适用：`feature-1.4.0` 分支上的并行开发

## 零、分工

| 端 | 机器 | 环境 | 主战场 |
|---|---|---|---|
| **业务端（core）** | 本机 | Windows，**无 NVIDIA 显卡**，有 JDK17 / Maven / Node | 短剧库业务代码：迁移、实体、服务、接口、前端 |
| **引擎端（engine）** | 家里 | Windows，**RTX 4060 Ti 16G**，ComfyUI | 本地模型引擎：ComfyUI 编排、音频引擎、网关、启停脚本 |

两端**同在 `feature-1.4.0` 一条分支上**，靠目录隔离与契约冻结避免互相破坏。这是一份"两个人都照它做就不会打架"的清单，不是建议。

## 一、为什么需要这份文档

目录不重叠时 git 本身不会冲突，但有三样东西是共享的，一旦各自发挥，合并时必然对不上：

1. **Flyway 迁移版本号**是全局唯一的，两边都加就撞号，而 `outOfOrder=false` 下撞号会让生产迁移直接失败。
2. **跨端接口**（引擎 HTTP + `runtime.json`）是唯一耦合点。业务端本机无显卡，只能用 mock 验证，契约不准的话回家一跑就崩。
3. **`pom.xml`** 两端都可能手痒去加依赖，改同一处就是硬冲突。

下面逐条定死。

## 二、目录所有权

| 路径 | 归属 | 规则 |
|---|---|---|
| `src/main/java/**` | 业务端 | 引擎端不碰 |
| `src/main/resources/**`（除 `db/migration`） | 业务端 | 引擎端不碰 |
| `web/**` | 业务端 | 引擎端不碰 |
| `app/docs/**` | 业务端 | 只写已实现，改前先看实现 |
| **`src/main/resources/db/migration/**`** | **业务端独占** | **引擎端一律不新增、不修改**（见第三节） |
| `script/local-video/**` | **引擎端独占** | 业务端只读不写，除对接调试外不动 |
| `app/design/**` | 共用 | 谁改谁在 commit message 里写一句改了什么 |
| `pom.xml` | **业务端独占** | 引擎端若确实需要 Java 依赖，先在约定文档里登记，由业务端加 |
| `Dockerfile`、`script/deploy/**`、`script/build.sh` | 业务端 | 引擎端涉及镜像体积时必须先说 |

**判断口诀**：改的东西会不会进 `mvn package` 的产物？会 → 业务端的；不会且只在 GPU 机器上跑 → 引擎端的。

## 三、Flyway 编号：业务端独占分配

**硬约束**：Flyway 默认 `outOfOrder=false`，**不允许先跑 V13 再补 V12**。两边各加一个 V12，第二个人推上去后，第一台机器拉下来就会在启动时炸掉，且报错信息不直观。

### 3.1 分配表

| 版本 | 内容 | 归属 |
|---|---|---|
| V12 | 短剧库 · 文字层（6 张表：剧/集/人物/场景/物品/分镜） | 业务端 |
| V13 | 短剧库 · 视觉层（6 张表 + 一期 7 字段 alter） | 业务端 |
| V14 | 本地模型服务（`t_local_grant` 等，**仅当引擎端确实需要持久化时**） | 业务端 |
| — | 引擎端自行分配 | **无。引擎端不写迁移。** |

### 3.2 引擎端要建表怎么办

引擎端**不写 SQL**，只交一份字段清单给业务端（写在 commit message 或 `app/design/` 下），由业务端落成 V14。这样保证编号单点分配，不会撞。

### 3.3 开工前自检

```bash
ls src/main/resources/db/migration/postgresql/ | grep -oE '^V[0-9]+' | sort -V | tail -3
```

当前最新应为 **V11**。动手加迁移前先跑这条，别凭记忆。

## 四、跨端契约（冻结，改动需双方确认）

这是两端唯一耦合的地方。**契约先于实现**：任一端要改字段，先在本文档改，双方确认后再改代码。

### 4.1 端点总表

| 方法 | 路径 | 用途 | 状态 |
|---|---|---|---|
| POST | `/v1/videos/generations` | 提交视频生成任务 | 已实现（mock 验证） |
| GET | `/v1/videos/generations/{id}` | 查任务 | 已实现 |
| GET | `/v1/videos/generations` | 列任务（最多 50） | 已实现 |
| POST | `/v1/videos/generations/{id}/cancel` | 取消 | 已实现 |
| POST | `/v1/images/generations` | 提交图像生成 | **待引擎端实现** |
| GET | `/v1/images/generations/{id}` | 查任务 | **待实现** |
| POST | `/v1/audio/speech` | TTS 合成 | **待实现** |
| GET | `/v1/audio/speech/{id}` | 查任务 | **待实现** |
| POST | `/v1/audio/lipsync` | 口型对齐 | **待实现** |
| GET | `/v1/audio/lipsync/{id}` | 查任务 | **待实现** |
| GET | `/v1/models` | 列出可用模型 | 已实现 |
| GET | `/health` | 引擎健康与显存 | 已实现 |

约定：**提交类端点一律返回 202 + 任务对象，查询类端点一律返回任务对象**。不引入同步阻塞接口——视频要跑 4~6 分钟，同步接口必然超时。

### 4.2 任务对象（所有能力共用同一形状）

```json
{
  "id": "task_20261110_172000_a1b2c3",
  "status": "succeeded",
  "kind": "video",
  "model": "wan2.2-ti2v-5b",
  "created_at": "2026-11-10T17:20:00+08:00",
  "started_at": "2026-11-10T17:20:03+08:00",
  "finished_at": "2026-11-10T17:24:41+08:00",
  "output_path": "D:/StoryForgeLocal/output/20261110/task_xxx.mp4",
  "seed": 1827364,
  "elapsed_ms": 278000,
  "duration_ms": 5042,
  "error": null
}
```

| 字段 | 说明 |
|---|---|
| `status` | `queued` / `running` / `succeeded` / `failed` / `canceled`，**只有这五个值** |
| `kind` | `image` / `video` / `speech` / `lipsync` |
| `output_path` | **绝对路径**，文件必须已落盘；业务端据此读或搬文件 |
| `seed` | 实际使用的 seed（不是请求里的 0），抽卡复现靠它 |
| `elapsed_ms` | 排队+执行总耗时，前端用来显示进度 |
| `duration_ms` | 产出媒体的时长（视频/音频），按**纠正后**的帧数或采样数算 |
| `error` | 成功为 `null`，失败为 4.4 的错误对象 |

> **兼容说明**：现有实现返回的是 `video_path` 字段，本次统一为 `output_path`。引擎端改的时候保留 `video_path` 作为别名，避免旧测试脚本全红。

### 4.3 提交请求（视频，现有实现为基础）

```json
{
  "model": "wan2.2-ti2v-5b",
  "prompt": "年轻女人坐在窗边，暖光，中景",
  "negative_prompt": "模糊, 畸形, 多手指",
  "width": 704,
  "height": 1280,
  "num_frames": 121,
  "fps": 24,
  "seed": 0,
  "start_image": "base64 或绝对路径，可选",
  "end_image": "base64 或绝对路径，可选"
}
```

引擎端**必须回报纠正后的实际参数**（新建任务时写入任务对象或返回体的 `applied` 字段），因为：

- 宽高会被纠到 32 的倍数（720 → 704）
- 帧数会被纠到 8n+1（120 → 121）
- seed 传 0 表示随机，实际值必须回传

业务端要拿纠正后的值算真实时长，否则时间轴对不上。

### 4.4 错误响应（本次新增，必须统一）

现有实现返回 `{"error": "字符串"}`，业务端无法据此判断该提示用户什么、该不该重试。统一为：

```json
{
  "error": {
    "code": 40204,
    "message": "显存不足，无法加载 wan2.2-ti2v-5b（需要 14.6G，可用 1.2G）",
    "stage": "load_model",
    "retryable": false
  }
}
```

`retryable=true` 的才允许业务端自动重试（如排队超时）；`false` 必须展示给用户。

错误码分段（**业务端在 `ErrorCode` 里预留同名，引擎端在响应里用 `code` 回传**）：

| 码 | 含义 | 可重试 |
|---|---|---|
| 40200 | 本地服务未启用 | 否 |
| 40201 | 引擎未安装 | 否 |
| 40202 | 引擎启动失败 | 是（一次） |
| 40203 | 引擎启动超时 | 是（一次） |
| 40204 | 显存不足 | 否 |
| 40205 | 模型文件缺失 | 否 |
| 40206 | 队列已满 | 是 |
| 40207 | 任务不存在 | 否 |
| 40208 | 生成失败（引擎内部错误） | 是（一次） |
| 40209 | 输出文件缺失 | 否 |
| 40210 | 未授权使用该能力 | 否 |
| 40211 | 超出日配额 | 否 |
| 40212 | 模型与能力不匹配 | 否 |
| 40213 | 许可不允许商用 | 否 |
| 40214 | `runtime.json` 缺失或损坏 | 是（一次） |
| 40215 | 引擎被占用（exclusive 冲突） | 是 |
| 40216 | 输入参数非法 | 否 |
| 40217 | 引擎进程消失 | 是（一次） |
| 40218 | 任务已取消 | 否 |
| 40219 | 预留 | — |

### 4.5 runtime.json（引擎端写，业务端读）

位置：`D:/StoryForgeLocal/data/local-ai/runtime.json`（**不放仓库**，每次重启重建）

```json
{
  "schemaVersion": 1,
  "gateway": { "pid": 12340, "port": 8199, "startedAt": "2026-11-10T17:00:00+08:00" },
  "engines": {
    "comfyui": {
      "pid": 12345, "port": 8188, "state": "ready",
      "loadedModel": "wan2.2-ti2v-5b", "vramMb": 14600,
      "startedAt": "2026-11-10T17:00:12+08:00", "lastUsedAt": "2026-11-10T17:24:41+08:00"
    },
    "audio": {
      "pid": null, "port": 8190, "state": "stopped",
      "loadedModel": null, "vramMb": 0,
      "startedAt": null, "lastUsedAt": null
    }
  },
  "vram": { "totalMb": 16384, "freeMb": 1200, "headroomMb": 800, "measuredAt": "2026-11-10T17:24:41+08:00" }
}
```

| 字段 | 约束 |
|---|---|
| `schemaVersion` | 整数，当前 `1`。加字段不改它；**删字段或改语义必须加 1** |
| `state` | `stopped` / `starting` / `ready` / `busy` / `crashed` |
| `loadedModel` | 当前驻留模型 key，`null` 表示已卸载 |
| `vramMb` | 该引擎占用显存（MB） |
| `freeMb` | 实测可用显存，业务端做容量判断用 |

**业务端绝不把端口存进数据库**。桌面版端口是动态的，存了就必然失效；每次调用现读 `runtime.json`。

### 4.6 能力位 → 引擎映射

| 能力位 | 引擎 | 模型示例 |
|---|---|---|
| `IMAGE` | `comfyui` | `sdxl-illustrious`、`flux-schnell` |
| `VIDEO` | `comfyui` | `wan2.2-ti2v-5b` |
| `AUDIO` | `audio` | `cosyvoice2-0.5b`（TTS）、`latentsync`（口型）、`faster-whisper`（ASR） |

`IMAGE` 与 `VIDEO` **共用 comfyui 引擎进程**，换模型用 `POST /free` 卸载再加载，**不重启进程**（重启要多花 20 秒）。`AUDIO` 必须独立进程与独立 venv，torch 版本会冲突。

`t_local_grant` 按**能力位**授权（`IMAGE,VIDEO,AUDIO` 的逗号串），不是整体开关。

### 4.7 端口与超时

| 项 | 值 |
|---|---|
| 网关 | 8199（固定） |
| ComfyUI | 8188（固定） |
| 音频引擎 | 8190（固定） |
| 视频任务超时 | **480 秒**（4~6 分钟是常态，别设 60s） |
| 图像任务超时 | 180 秒 |
| TTS 任务超时 | 90 秒 |
| 引擎冷启动 | 40~70 秒，**首次调用必须预热提示** |
| 全局并发 | 视频 2 路、FFmpeg 1 路（串行） |

端口固定是为了降低复杂度，**但业务端仍要读 `runtime.json` 而不是硬编码**——将来支持多实例时不用改代码。

## 五、同步与合并

### 5.1 每日节奏

```bash
# 开工第一件事
git fetch origin
git merge origin/feature-1.4.0     # 用 merge，不要 rebase

# 收工前
git fetch origin && git merge origin/feature-1.4.0
git push origin feature-1.4.0
```

**用 `merge` 不用 `rebase`**：rebase 会改写对方已经拉取的提交，两边都在推的时候会互相打架。

### 5.2 提交粒度

**一个可运行的小步就提交**，不要攒一天。理由：两端并行时，任何一方攒大批改动，另一方 pull 下来如果出问题，根本定位不到是哪一步坏的。

commit message 前缀区分来源，便于以后过滤：

- 业务端：`feat(drama): ...` / `fix(...)` / `docs(...)`
- 引擎端：`feat(engine): ...` / `fix(engine): ...`

### 5.3 永不入库的东西

两端都必须遵守。引擎端尤其注意——模型权重动辄 17G。

```
app/script/local-video/.venv/
app/script/local-video/output/
app/script/local-video/logs/
app/script/local-video/.pids.json
app/script/local-video/**/__pycache__/
app/script/local-video/workflows/*.json      ← 用户本机从 ComfyUI 导出的，与版本绑定
D:/StoryForgeLocal/**                        ← 模型、ComfyUI 本体、runtime.json
web/node_modules/
web/dist/
```

提交前先看 `git status`，**看到 `??` 里有 `output` / `.venv` / `*.safetensors` 立刻停下**。

## 六、本机（无 GPU）怎么验引擎对接

业务端本机没有 NVIDIA 显卡，跑不了真模型。两层验证：

**第一层：引擎端自测（家里跑，真机）**
`gateway/test_mock.py` 用 mock ComfyUI 跑全链路 18 项断言，不需要显卡；真机再补一轮实拍验证。

**第二层：业务端 mock 对接（本机）**
引擎端提供一个**假网关模式**（`--mock` 启动，或独立 `mock_gateway.py`），行为：

- 端点、状态机、错误码与真网关完全一致
- `sleep(2)` 后返回 `succeeded`，`output_path` 指向一个 1 秒的占位 mp4
- 显式支持错误码注入（环境变量指定返回 40204 / 40206 / 40217），用来验证业务端的错误分支

业务端接 `VideoProvider.LOCAL` 时只连这个假网关。**契约不准，回家一跑就崩——这是双端并行最大的风险点，靠第六节和第四节共同兜住。**

## 七、合并前检查清单

两端各自在 push 前跑一遍：

```bash
# 1. 工作区干净
git status --short

# 2. 迁移编号连续、无跳号
ls src/main/resources/db/migration/postgresql/ | grep -oE '^V[0-9]+' | sort -V

# 3. 契约文件没被单方面改过
git diff origin/feature-1.4.0 -- "design/2026-11-10-1.4.0-双端并行开发约定.md"

# 4. 后端测试（业务端）
mvn -q -DskipTests=false test

# 5. 前端构建（业务端）
cd web && npm run build

# 6. 引擎自测（引擎端）
python gateway/test_mock.py
```

第 3 条是重点：**契约文件出现非预期 diff，说明有一端单方面改了接口**，必须先对齐再合并。
