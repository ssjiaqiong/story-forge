## 一、1.4.0 做什么

### 1.1 一句话

从一部小说出发，逐镜生成带原生对白音轨的短剧视频，**每一镜都由作者抽卡选定**，全部镜头过审后合成当前剧集。

### 1.2 范围边界

| 层 | 内容 | 归属 | 说明 |
|---|---|---|---|
| 文字层 | 短剧项目 → 简介 / 人物 / 场景 / 物品 / 剧集 / 分镜 | 一期（V12） | **1.4.0 必须一起做**，它是视觉层的唯一输入源 |
| 资产层 | 人物视图 / 场景视图 / 道具视图的定妆图 | 二期（V13） | 抽卡的参考素材 |
| 生成层 | 逐镜静帧 → 逐镜视频（原生同出）→ 抽卡 → 定稿 | 二期（V13） | 本文重点 |
| 合成层 | 整集拼接 + 字幕 + 封面 | 二期（V13） | 只做 `-c copy` 拼接 |

**明确不做（1.4.0）**：背景音乐生成、配乐卡点、动态字幕特效、4K 输出、多语言配音（只做中文）、横屏（只做 9:16）、一键发布到短剧平台。

### 1.3 为什么文字层不能推后

视觉层每个镜头的输入是：`分镜行（景别/时长/动作/台词）+ 人物视图 + 场景视图 + 道具视图 + 上一镜尾帧`。这些全部来自文字层。文字层不落地，视觉层没有输入，只能拿 demo 数据跑，验证不了真实改编质量。所以 1.4.0 必须两层一起上。

## 二、决策：为什么改成原生同出

### 2.1 三条路线的重新比较

| 路线 | 口型 | 音色 | 环节数 | 单集成本（90s） |
|---|---|---|---|---|
| A 画先声后（原主链路） | 不同步，靠中景/侧身规避 | **完全可控**（TTS） | 视频 → TTS → 混音 → 拼接 | ¥80~150 |
| B 声先画后（音频驱动） | 最准 | **完全可控** | TTS → 驱动 → 拼接 | ¥150~250（且只能口播） |
| **C 原生同出** | **天生同步** | 需音频参考约束 | 视频（含音轨）→ 拼接 | ¥230~320 |

原设计不选 C 的理由是「音色会漂，第 3 集和第 8 集同一角色声音会变」。这个理由在 2026 年 11 月已经不成立了——**Vidu 的参考生视频接口接受 `sounds` 参数（最多 3 段、每段 3~12s 的 mp3），用该角色的音色样本约束生成音轨**。音色从「模型随机决定」变成「由音色样本锚定」。

### 2.2 原生同出的四个真实收益

1. **口型不需要修**。省掉 lip-sync 环节（$0.018/s）和「修完脸崩」的风险，也省掉「时长对不上要重录 TTS」的返工。
2. **表演跟着话走**。模型的呼吸、停顿、重音、微表情与台词在同一时间线上生成，这是后贴音频永远做不到的。
3. **环境音/音效一并产出**。关门声、脚步、雨声随画面生成，省掉后期贴音效（原来这一项在成本表里被严重低估）。
4. **剪接点天然对齐**。一次生成就是一个完整乐句，拼接处不会出现「画面已经结束但话没说完」。

### 2.3 原生同出的四个代价（以及对策）

| 代价 | 具体表现 | 对策 | 见章节 |
|---|---|---|---|
| 音色仍可能漂 | 同一角色跨镜音色微变 | 音频参考 + 声音克隆 + 声轨替换兜底 | §4 |
| 改一个字要整镜重生 | 台词改 → 已抽的 take 全作废 | 台词在拆解阶段冻结，产品上加锁 | §4.4 |
| 时长是档位不是任意值 | 3~16s，落不进档位的台词要拆镜 | 分镜按语速预排时长，超限自动拆 | §5.2 |
| 抽卡成功率低于无声视频 | 多一个音频维度要评判，复杂场景 <60% | 单镜上限提到 5，可降级「只抽画面」 | §7.2 |

**结论**：原生同出作为主链路（C），保留 A 作为降级路线（供应商故障、或某镜反复抽不出来时用）。B（口型驱动）在 1.4.0 **不实现**——原生同出已经覆盖了口型需求，再引入 B 是重复建设。

## 三、支持原生音画同出的模型（核心章节）

### 3.1 先给「原生同出」定标准

这个词被厂商滥用了，必须分清三种成色，否则选型会被宣传话术带偏：

| 等级 | 定义 | 判定方法 |
|---|---|---|
| **L1 真同出** | 一次推理同时产出画面与含对白的音轨，口型由同一次推理对齐 | API 有独立 `audio` / `native_audio` 开关，且文档写明 synchronized / native；产物是**单文件带音轨** |
| L2 补音频 | 先出无声视频，同一服务内再跑一遍配音/口型对齐 | API 分两步（先 video 后 audio），产物两段再合并 |
| L3 后贴（非原生） | TTS + lip-sync 外部拼装 | 就是本文的路线 A/B |

**1.4.0 只接 L1。**

### 3.3 五个决定性参数，逐条说明为什么

**① 参考图上限 —— 直接决定「四类视图能不能一起喂」**

你的需求是「分镜材料 + 前一分镜最后画面 + 人物视图 + 场景视图 + 特殊道具视图」。算一下一镜要几槽：

| 槽位 | 张数 | 说明 |
|---|---|---|
| 本镜静帧（首帧） | 1 | 构图定死的锚 |
| 上一镜尾帧 | 1 | 连戏（可用「宽松」模式退化为参考） |
| 主人物视图 | 2~3 | 正脸 + 3/4 侧 + 全身 |
| 次人物视图 | 2 | 双人镜才需要 |
| 场景视图 | 1~2 | 全景 + 局部 |
| 特殊道具 | 1 | 剧情道具 |
| **合计** | **8~10** | |

- **Seedance 2.5（30 张）**：宽裕，还能塞服装变体、光线参考
- **Vidu Q4（15 张）**：刚好够，余量用来放尾帧和换装
- **Kling 3.0 Omni（7 张）**：**不够**，双人镜必须砍槽位 → 只能放 1 首帧 + 1 尾帧 + 2 主人物 + 1 次人物 + 1 场景 + 1 道具
- **Veo 3.1（3 张）**：**完全不够**，直接排除

**② 音频参考 —— 这是音色可控的唯一手段**

只有三家支持：

| 模型 | 参数 | 形式 | 能干什么 |
|---|---|---|---|
| **Vidu Q4** | `sounds` | 0~3 段 mp3，每段 **3~12s** | 传该角色音色样本 → 生成音轨向该音色靠 |
| **Seedance 2.5** | `audio` 参考 | 10 段，合计 ≤30s | 同上，但段数多、可放多人 |
| Hailuo H3 | 音频参考 | 3 段 | 同上 |

**这一条是选型的决定性依据**。没有音频参考的原生同出（Kling、Vidu Q3、Veo）等于把音色交给模型随机，跨集必漂。

注意 Vidu 的 3~12s 限制：**音色样本必须剪成 3~12 秒**，太短学不准，太长传不进去。所以每个角色需要一段「标准音色样本」。

**③ 单次时长 —— 决定一镜能不能装下一句完整台词**

按中文 4 字/秒（短剧正常语速）：

| 时长 | 可装台词 | 适合 |
|---|---|---|
| 3~5s | 12~20 字 | 短句、反应镜、空镜 |
| 6~10s | 24~40 字 | 常规对白镜（**主力区间**） |
| 11~16s | 44~64 字 | 长台词、独白、双人对答 |
| 17~30s | 68~120 字 | 只有 Seedance 2.5 / Wan 3.0 能做，**但一镜 30 秒在短剧里节奏太慢，不用** |

短剧单镜通常在 2~8 秒。所以 **3~16s 完全够用**，Seedance 的 30s 优势在短剧场景里用不上。

**④ 分辨率 —— 竖屏成片下限 1080×1920**

- **Seedance 2.5 的 API 只有 480p/720p** —— 这是硬伤。720p 竖屏 = 720×1280，放到手机上明显糊。官方宣传的 4K 是消费端（即梦）能力，API 没有。**因此 Seedance 2.5 只能做草稿档，不能做定稿。**
- Vidu Q4 支持到 4K，Kling 3.0 Omni 支持 4K，但 1G 内存的服务器处理不了 4K，1.4.0 统一 1080p。

**⑤ 价格 —— 按「生成量」而不是「成片量」算**

抽卡意味着生成量 = 成片量 × 抽卡倍数。1.4.0 默认每镜抽 3 次，实际可用率按 60% 折算需要 1.7 倍，取 3 倍留余量。

### 3.4 选型结论


### 3.5 一个必须说清的产品分层：Q3-Drama 的整集模式

Vidu 有一个 **Q3-Drama**，专门为「连续剧」调过，接受**整集脚本**一次生成。接口形态：

```
scriptContent:
  Character: 苏晚
  [Visual Style: 治愈系实拍，暖黄柔光，室内复古陈设]

  Shot 1-1: (2s Medium Shot Eye-level Fixed)
  @苏晚 坐在窗边，用软布轻擦一只碎花瓷杯。
  @苏晚: 一个安静的下午，只有我和我最喜欢的杯子。

  Shot 1-2: (2s Close-up High-angle Fixed)
  ...
assets: [角色图, 场景图, 道具图]
duration / resolution: 1080p / aspectRatio: 9:16
```

**它一次输出一整集（含多镜头切换 + 原生音画）**。听起来很美好，但和你的诉求直接冲突：

| | 整集模式（Q3-Drama） | 逐镜模式（Q4） |
|---|---|---|
| 抽卡单位 | **一集**（18 个镜头一起重来） | 一镜 |
| 单次成本 | 一集全量 | 一镜 5 秒 |
| 你能改的东西 | 只能改脚本再整集重生 | 任何一镜单独重抽 |
| 符合「逐镜审核」 | ❌ | ✅ |

一镜不满意要重跑整集，成本是逐镜的 18 倍，而且你无法控制某一镜。所以：

**Q3-Drama 降级为「预演模式」**——在正式抽卡前，用整集脚本出一版低清预演片（540p/720p），用来快速判断：分集节奏对不对、选角像不像、台词密度合不合适。看完预演再进逐镜精做。这一层很便宜，且能大幅减少逐镜抽卡的浪费。

## 四、音色漂移的三个解法（原生同出的死穴）

### 4.1 三级递进方案

```
第 1 级  音色样本锚定（必做，几乎零成本）
         每个角色建一份 3~12s 音色样本，抽卡时作为 sounds 传入。
         覆盖 80% 的漂移问题。

第 2 级  原生音轨替换（默认开启，成本≈0）
         原生同出的音轨保留「口型时机」和「表演节奏」，
         但把它的声音换成固定音色的 TTS。
         因为台词文本相同、语速接近，口型仍然对得上。

第 3 级  整镜重生（兜底）
         换 seed / 换参考图权重 / 降级到路线 A。计入抽卡预算。
```

### 4.2 第 1 级：音色样本怎么来

| 来源 | 做法 | 质量 | 成本 |
|---|---|---|---|
| 声音克隆 | 用户上传 30s 真人录音 → `voice-clone` 生成音色 → TTS 念一段标准台词 10s → 存为样本 | 最好，可控 | 一次性 |
| TTS 直出 | 从平台音色库选一个 → TTS 念 10s 样本 | 好，省事 | ≈0 |
| 上一镜原生音轨 | 取第 1 镜的原生音轨（该角色第一句）截 8s 当样本 | 一般，会累积漂移 | 0 |

**1.4.0 用第 2 种（TTS 直出）**：每个角色在人物表里选定音色 → 系统自动生成 10s 样本 → 存进 `t_drama_voice.sample_url`。这样「人物表的音色」和「生成时的音色约束」是同一个东西，不会脱钩。

Vidu 的 `sounds` 最多 3 段，所以**一镜里最多固定 3 个角色的音色**。双人镜够用，三人以上群戏要把次要角色退化为「不传样本」。

### 4.3 第 2 级：声轨替换为什么能对得上

原生同出的口型是按模型自己念的台词生成的。如果换成同样文本的 TTS，偏差来自两处：**断句不同** 和 **语速不同**。

工程做法：

1. 抽卡时记录原生音轨的 `duration_ms`
2. 生成 TTS 时指定 `speed`，让 TTS 时长逼近原生时长
3. 校验：`|TTS时长 - 原生时长| / 原生时长 ≤ 8%` 才允许替换；超过就重跑 TTS（调 speed），两次仍超就标记该镜「音画需人工」
4. 替换只换音频轨，视频轨不重编码（`ffmpeg -map 0:v -map 1:a -c:v copy -c:a aac`）

这样既能拿到原生同出的表演和口型，又能拿到完全一致的音色。代价只是一次几乎不要钱的 TTS。

> **为什么默认开启第 2 级**：AI 原生音轨的音色即使有样本约束，跨集会累积漂移，而观众对「同一角色声音变了」极其敏感。用 TTS 兜住音色，是零成本换稳定。

### 4.4 台词冻结机制（防止「改一个字整镜作废」）

原生同出下，台词是生成输入的一部分。改了台词，已抽的 take 全部作废。

产品设计：

| 状态 | 允许做什么 | 提示 |
|---|---|---|
| 台词 `DRAFT` | 随便改 | 无 |
| 台词 `FROZEN`（进生成前自动置为此状态） | 改需二次确认 | 「本镜已有 N 个 take，改台词将全部作废，预计重抽成本 ¥X」 |
| 已有 `SELECTED` take | 改台词需先取消定稿 | 同上，并提示「已定稿的镜头会被标记为待重做」 |

不做「自动作废」，一律要作者在确认框里点。这个坑跟 1.3.6 修的「按分析修改覆盖定稿章节」是同一类问题。

## 五、分镜规格（原生同出对文字层的硬约束）

一期文档已有 §7.5「分镜要按拍摄纪律写」，这里补三条原生同出特有的：

### 5.1 一个镜头只能有一次发声

原生同出按「一次生成 = 一个完整乐句」工作。一镜里出现两人交替说话，模型会把两句话挤在一起或吞掉一句。

规则：
- 一镜只能有一句台词，说话人明确
- 双人对话必须拆成两个镜头（正反打）
- 不允许「旁白 + 角色说话」同镜

### 5.2 镜头时长必须落在档位内，且按语速反算

```
镜头时长 = ceil(台词字数 / 4) + 1   （秒，向上取整到整数，+1 秒留表演余量）
若 > 16  → 必须拆镜
若 < 3   → 补一个反应镜合并，或改为无台词镜
```

举例：「你这个人怎么这么不讲道理」= 12 字 → 12/4 + 1 = 4 秒。可直接生成。
「我告诉你，这个家我一天也待不下去了，你爱怎么办就怎么办吧」= 28 字 → 28/4+1 = 8 秒。可以。
超过 60 字的长台词 → 必拆。

### 5.3 景别要配合「音色样本能不能起作用」

音频参考是全局的，模型不知道「这一镜该突出谁的声音」。所以：

- **正脸单人镜**：音色最容易对齐，适合放关键台词
- **双人同框**：声音会混，且 Vidu 只能传 3 段样本，优先保主角
- **背影/远景**：口型不可见，**不传样本**，省下来给别的镜

这条要写进分镜提示词：`声音焦点：<角色名>`，提示词生成器据此决定传哪几段样本。

## 七、抽卡与审片（原生同出后的变化）

### 7.1 镜头状态机

```
PENDING ──生成静帧──> FRAME_READY ──抽卡──> TAKE_READY ──定稿──> SELECTED
                                                          │
   （改台词 / 改资产版本 / 换供应商）──> STALE <───────────┘
```

`STALE` 是关键：任何上游变更都要让已定稿镜头显式失效，不能悄悄用旧素材合成。

### 7.2 抽卡上限与成功率的现实

第三方实测反馈：Vidu Q3 在复杂剧情场景下**成片率不到 60%**。原生同出因为多了音频维度，成片率更低。

所以：
- 单镜默认上限 **5 次**（不是 3 次），可配到 8
- 前 2 次用便宜档（720p），选定后再用 1080p 重生成一次做定稿（"草稿-定稿"两段式）
- 连续 3 次同因失败 → 提示「建议改分镜」（因为多半是分镜写得不适合生成，不是运气问题）

### 7.3 审片的两个视角

1. **单镜视角**：这个 take 本身好不好（画质/表演/口型/音色）
2. **连看视角**：按镜号顺序连续播放已定稿的镜头，看节奏和连戏

连看视角是原生同出之后**更需要**的功能——因为每镜都是独立生成的，镜头之间的色调、光线、人物状态容易跳。必须能连续播着看才能发现。

## 九、接口与 AI 场景（在视觉层基础上调整）

### 9.1 `AiConfigKind` 增两个


### 10.2 24 集 × 90 秒

- 正片 2160 秒，单镜平均 5 秒 → **432 镜**
- 每镜「2 次草稿 + 1 次定稿」= 3 次，每次 5 秒 → 生成量 **6480 秒**

| 方案 | 成本 | 单集 |
|---|---|---|
| 全 Vidu Q4 1080p | ≈**¥5,508** | ¥230 |
| 草稿 Vidu 540p + 定稿 Vidu 1080p | ≈**¥3,300**（6480s 中约 2/3 走 540p） | ¥138 |
| 全 Kling 3.0 Omni 1080p+音 | ≈**¥7,711** | ¥321 |
| 全 Seedance 2.5 480p | ≈**¥4,147** | ¥173 |

**推荐「草稿-定稿两段式」**：前 2 次用 540p 便宜档抽，选定后 1080p 重生成一次。成本从 ¥230/集 降到 **¥138/集**，质量不受损（因为便宜档只用于「选哪个表演对」，不用于出片）。

### 10.3 与路线 A 的净成本对比

路线 A 的 ¥80~150/集 里不含：音效生成、口型修正、TTS 时长校验返工。原生同出把这些都吃掉。按实际工时算，原生同出反而更省——但**成本是显性支出，工时是隐性支出**，这是用户要自己权衡的。

**必须做「先试拍 1 集」**：实付 ¥150~250 就能验证成片率、音色稳定性、成本真实值。不试拍直接跑 24 集是不可接受的。

## 附录 A：送原生同出模型的提示词六段式

```text
[锁定]  人物与场景必须严格来自参考图：{{主角名}}（正面/侧面/全身）、{{场景名}}、{{道具名}}。
        画面风格：{{style}}。竖屏 9:16，写实质感，自然光。

[表演]  {{主角名}} {{动作描述}}，情绪{{情绪}}，语速{{快/中/慢}}。
        表演细节：{{呼吸/眼神/手部动作}}。

[台词]  {{主角名}}：「{{台词}}」
        仅此一句，不要新增台词，不要旁白。

[运镜]  {{景别}}，{{机位高度}}，{{固定/缓推/缓摇}}，一镜到底不剪切。

[声音]  环境音：{{雨声/室内安静/街道远景}}。音效：{{关门声/瓷器碰撞}}。
        声音焦点在 {{主角名}}，其他人物不发声。

[禁止]  不要出现文字、水印、字幕；不要换脸、不要多手多指；
        不要切镜；不要在台词结束后继续说话。
```

六段的顺序不能变：锁定 → 表演 → 台词 → 运镜 → 声音 → 禁止。实测把「禁止」放在最前面会削弱前面的指令，放在最后才压得住。
