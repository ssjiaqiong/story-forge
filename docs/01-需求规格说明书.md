## 1. 文档说明

### 1.1 目的

定义 StoryForge（AI 长篇小说创作平台）的已交付业务规则、功能需求、非功能需求与验收标准，作为开发、测试与验收的共同依据。

### 1.2 范围

**平台形态**：用户即数据空间（无租户/组织概念），账号由超级管理员统一开通，不开放自助注册。

**已交付能力**：

- 账号与权限：登录、双令牌、登出、改密、首次登录强制改密；超管用户管理；超管小说查看与已删除小说物理清理
- 设置中心：AI 接口（文本 / 图像）、AI 场景绑定、联网搜索源与场景绑定、提示词模板（指令层可编辑）
- 创作主线：书架 → AI 蓝图开书 / 只建草稿 / 拆书改编 / 灵感对话开书 → 小说工作台（设定、总纲、章节正文、人物与关系、属性背包、势力、物品、事件池、章节分析、按分析修改、智能助手、封面）→ 小说整本 JSON 导出与导入 / TXT 成品导出
- 数据与统计：多用户数据隔离、AI 用量记录、仪表盘聚合统计
- 交付形态：单端口 Web（前后端同源）、Docker/Compose 部署、Nginx HTTPS 网关、TCR 镜像、Windows 桌面版（SQLite）、三数据库支持

**范围边界**（不是待办，是明确不做）：租户/组织/团队与多人协作、移动端 App、订阅计费、版权查重、第三方平台发布、图片/音频/视频之外的模型接入。

### 1.3 术语表

| 术语 | 含义 |
|---|---|
| 用户 User | 平台唯一账号形态；每个用户即一个完全独立的数据空间 |
| 数据隔离 | 业务表以 `user_id` 为归属字段，框架层自动追加过滤条件，跨用户不可见、不可写 |
| 小说 Novel | 一部作品，一个用户下可有多部；状态 DRAFT 草稿 / WRITING 连载中 / FINISHED 已完结 / ARCHIVED 已归档 |
| 设定 SettingDoc | 小说级文本块，五类：世界观 WORLDVIEW / 背景 BACKGROUND / 核心冲突 CORE_CONFLICT / 核心看点 HIGHLIGHT / 文风 STYLE |
| 总纲 MasterOutline | 小说级大纲条目（标题 + 正文），可 AI 批量生成，与章节多对一关联 |
| 章节 Chapter | 单章载体，含卷号、卷名、章号、标题、摘要、正文、汉字数、状态（DRAFT / WRITING / DONE）、关联总纲 |
| 人物 Character | 小说角色档案；定位 PROTAGONIST / SUPPORTING / ANTAGONIST / MINOR |
| 人物关系 Relation | 双端对称关系，类型：师徒 / 亲属 / 夫妻 / 恋人 / 好友 / 盟友 / 仇敌 / 对手 / 同门 / 其他 |
| 属性 Attribute | 人物当前值快照（数值或文本 + 单位），用于长篇一致性 |
| 背包 Inventory | 人物随身条目：ITEM 关联物品档案 / CURRENCY 货币 / MISC 普通物资 |
| 势力 Faction | 公司 / 帮派 / 国家 / 组织等；状态 ACTIVE / DORMANT / DESTROYED / DISBANDED |
| 物品 Item | 小说道具档案；状态 ACTIVE / DESTROYED / ABANDONED / LOST / CONSUMED |
| 事件 TimelineEvent | 事件池条目（标题、时间、描述、状态、参与角色）；状态 UNUSED / ONGOING / DONE / ABANDONED |
| 变更履历 ChangeHistory | 章节分析产生的要素变化记录：对象类型、字段、原状态、现状态、原因、正文依据 |
| AI 场景 Scene | 一个调用 AI 的功能单元，登记在 `AiScene`；用于场景绑定与提示词模板 |
| 提示词模板 | 用户可编辑的「指令段」；输出格式契约由系统锁定，不可编辑 |
| 蓝图 Blueprint | 书架开书时 AI 分段生成的设定草案（世界观 / 背景 / 简介与冲突 / 人物） |
| 创作约束 Constraint | 建书前 AI 追问、作者作答后拼成的「中文名：答案」多行文本，落库到小说，作为硬要求注入此后所有创作场景 |
| 拆书 Deconstruct | 上传成稿小说，AI 提炼主线后按改编档位重建一部新书（不生成正文） |
| 智能助手 Novel Agent | 工作台内的自然语言编辑助手，把指令转成结构化操作直接改库 |
| 自动写书 Auto Write | 按 cron 周期自动推进整本书「补总纲 → 补大纲 → 写正文 → 体检」的定时任务；一本书最多一条，启用期间该书只读 |

## 2. 背景与目标

### 2.1 背景

原有创作方式以文件系统与模型会话驱动：大纲、正文、角色、势力、事件库都是 Markdown 文件，存在多设备不可用、无隔离、无审计、多书难管理、状态同步依赖模型记忆等问题。

平台化方案采用「用户即空间」模型：每个用户拥有完全独立的创作空间（小说、设定库、AI 接口配置、提示词模板），账号由超管开通，超管仅额外拥有用户管理与小说查看两个平台能力。

### 2.2 目标

| 目标 | 可衡量指标 |
|---|---|
| G1 产品化 | 原本靠文件与对话完成的创作环节（开书 → 设定 → 大纲 → 正文 → 分析 → 改稿）全部可在 Web 上完成，产物结构化入库 |
| G2 数据隔离 | 任意跨用户读写被拒；数据同库共存但逻辑完全隔离 |
| G3 自带 AI | 未配置 AI 的用户无法触发生成；配置后可在页面内完成连通性测试；文本与图像接口分别配置 |
| G4 设定不漂移 | 章节分析把正文引起的人物/物品/势力/属性/背包变化写入变更履历并更新当前值 |
| G5 可带走 | 任意小说可导出为单个 JSON（含封面图片），导入到另一站点后数据完整、外键全部指向新记录；同一本书还可导出为 TXT 成品（卷名 + 章节 + 正文），直接投稿或发平台 |
| G6 账号管控 | 注册入口关闭；开号唯一路径 = 超管代建；超管不可修改他人创作内容 |
| G7 可交付 | 同一套代码支持 PostgreSQL / MySQL / SQLite，可容器部署、可打 Windows 桌面版 |

## 3. 角色与权限

| 角色 | 说明 | 权限要点 |
|---|---|---|
| 平台超管 SUPER_ADMIN | 平台运营方 | ①**首先是一个普通用户**，拥有用户全部能力（创作、AI 配置、导出）；②额外两个平台菜单：**用户管理**（建号/编辑/启停/重置口令/删除/恢复）与**小说管理**（跨用户只读查看小说、目录、正文；可对**已被用户逻辑删除**的小说做物理清除）；③不可停用/删除/重置自己，不可让系统失去最后一个启用的超管 |
| 普通用户 USER | 平台唯一账号形态 | 本人数据空间的全部能力：小说、设定库、章节正文、AI 配置、搜索配置、提示词模板、导入导出、仪表盘 |

## 4. 业务规则（BR）

| 编号 | 规则 |
|---|---|
| BR-01 | 除登录、刷新令牌、健康检查与接口文档外，所有接口必须携带有效 accessToken |
| BR-02 | 数据归属 `user_id` 一律由服务端从令牌解析，请求体中的用户标识被忽略 |
| BR-03 | 未配置可用 AI 接口时，生成类接口返回业务错误并引导去配置，不静默降级为本地拼装 |
| BR-04 | 同一用户下小说标题不可重复（不含逻辑删除数据）；重名创建/导入自动追加 `（2）`、`（3）` |
| BR-05 | 章号在小说内唯一；新增章节默认取当前最大值 +1；卷号与卷名为分组展示字段 |
| BR-06 | 章节状态流转为 草稿 → 写作中 → 已完成；状态为「已完成」时**正文与标题锁定**，只能通过改回草稿/写作中解锁 |
| BR-07 | 正文质量口径为**汉字数**（只统计中日韩统一表意文字，不含标点、数字、字母、空白）；小说总字数与章节数由服务端重算 |
| BR-08 | 设定按 `(user_id, novel_id, category)` 唯一；保存采用「整体覆盖」（旧行逻辑删除后重写），不得出现同分类重复行 |
| BR-09 | 小说下属数据（设定、角色、关系、属性、背包、势力、成员、物品、事件、参与者、章节、章节人物/事件、分析、履历、封面、助手会话）必须与小说同属一个用户；删除小说时一并逻辑删除，封面文件物理删除 |
| BR-10 | 人物关系对称录入：A→B 与 B→A 视为同一条，入库时按 `from_id < to_id` 归一；同一对角色同类型关系不可重复；不允许自己与自己建立关系 |
| BR-11 | 同一人物内属性名不可重复；同一人物不可重复挂同一物品档案 |
| BR-12 | 事件只能通过 AI 生成或拆书/导入产生，不提供手工新增入口；AI 生成的事件默认「未使用」，重名跳过，参与角色可复用已有角色或自动补建（单个事件最多补建 3 个） |
| BR-13 | 章节分析必须**按章节顺序**进行：前面章节都已分析过才能分析当前章；正文为空的章节返回错误并挡住其后章节 |
| BR-14 | 分析产生的变更必须写变更履历（章节、对象、字段、原状态、现状态、原因、正文依据）；原状态取自分析前的库内值，不采信模型自述；同一章重复分析时同一字段覆盖而非追加 |
| BR-15 | 属性与背包是「当前值快照」，分析同步时既写履历也**更新当前值**；人物档案其余字段只写履历不自动改写 |
| BR-16 | 「按分析修改」只生成不落库，必须由用户点保存才写入正文；保存后自动重新分析本章 |
| BR-17 | AI 密钥加密存储（AES-256-GCM），列表只回显掩码，不明文回显 |
| BR-18 | 停用账号后每次请求都从数据库校验状态，令牌立即失效 |
| BR-19 | 超管对他人小说的权限仅限只读；唯一写操作是物理清除**已逻辑删除**的小说及其关联数据，不可恢复 |
| BR-20 | 自助注册入口关闭：前端无入口，`POST /api/auth/register` 固定返回 `30030` |
| BR-21 | 初始超管与超管重置口令后，用户下次登录必须改密；改密前仅放行 `/api/auth/me`、`/api/auth/password`、`/api/auth/logout` |
| BR-22 | 每个用户只有一条灵感会话（库层唯一约束兜底），消息全部入库，刷新/换设备不丢 |
| BR-23 | 灵感技能按用户隔离：内置「创建小说」技能首次进入时复制到本人名下，可改可恢复默认，不可删除；修改只影响本人 |
| BR-24 | 灵感「一键创建小说」只能基于当前会话内容；创建成功后才询问是否清除会话 |
| BR-25 | AI 调用失败不得丢失用户输入：用户消息落库，失败回复以 `FAILED` 状态记录原因，且不进入后续上下文 |
| BR-26 | 拆书原文只用于当次分析，不落库；仅保留文件名、字数与拆解结果 |
| BR-27 | 导出文件为版本化 JSON（`format` + `formatVersion`），导入前校验格式与版本；导入时所有旧 ID 丢弃重建，外键按映射表重写 |
| BR-28 | 导入的数据归属当前登录用户；关联目标缺失的行跳过，不因单条脏数据导致整本失败 |
| BR-29 | 封面每部小说最多 5 张，可设主封面；取图需登录态，不做公开静态路径；删除小说级联清理记录与文件 |
| BR-30 | 所有 AI 调用必须经 `AiUsageService`，按场景落一条用量记录（成功与失败都记） |
| BR-31 | 所有调用 AI 的功能必须登记场景编码，并在「设置 → 提示词模板」中可编辑（未登记的场景不允许出现在模板列表） |
| BR-32 | 提示词模板只存「指令段」，输出格式契约由场景注册表提供并在渲染时追加，永远不入库、不可编辑 |
| BR-33 | 数据冲突以最新正文原文为权威来源，修正原因写入变更履历 |
| BR-34 | 数据库结构变更只通过 Flyway 迁移，禁止手工改表；PostgreSQL 基线是唯一事实来源 |
| BR-35 | 一本书最多一条自动写书任务（`(user_id, novel_id)` 唯一，不含逻辑删除数据）；周期表达式必须是 6 段式 cron，非法表达式拒绝保存（`40075`） |
| BR-36 | 自动写书任务启用且未暂停 / 未完成期间，该书进入只读态：一切写操作返回 `40073`，仅保留查看与导出；流水线自身的写库通过内部放行标记绕过该锁 |
| BR-37 | 自动写书一轮内严格串行，同一任务不重入（上一轮未结束则跳过本轮）；不并发写同一本书 |
| BR-38 | 章节大纲生成不跨总纲：一次生成只归属于同一条总纲；一条总纲该拆多少条章节大纲由故事本身决定，**不设固定条数**（「预计大纲数量」只是参考值），前一条总纲未标记完成前不推进下一条 |
| BR-39 | 自动写出的正文与手工写入共用同一个章节写入收口，历史版本来源记为 `AUTO_WRITE` |
| BR-40 | 连续 3 个周期执行失败、或体检硬伤数超过阈值时，任务自动转为暂停（`PAUSED`）并**同时解锁编辑**，必须人工介入后才能继续 |

## 5. 功能需求

### 5.1 认证与账号（AUTH）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-AUTH-01 | 登录 | 用户名 + 口令；返回 accessToken（30 分钟）与 refreshToken（7 天）；登录接口按 IP 限流 10 次/分钟 |
| FR-AUTH-02 | 令牌刷新 | refreshToken 换新 accessToken，旧 refreshToken 立即失效（轮换） |
| FR-AUTH-03 | 登出 | accessToken 的 `jti` 写入黑名单直至自然过期；传入的 refreshToken 一并吊销 |
| FR-AUTH-04 | 当前用户 | 返回用户名、昵称、角色、是否需强制改密 |
| FR-AUTH-05 | 修改口令 | 校验原口令，长度 ≥ 8 且含字母与数字；成功后强制重新登录 |
| FR-AUTH-06 | 强制改密 | 初始超管、超管重置口令的账号登录后被路由守卫拦到「修改口令」页 |
| FR-AUTH-07 | 注册关闭 | `POST /api/auth/register` 固定返回 `30030`；页面无注册入口 |
| FR-AUTH-08 | 令牌失效处理 | 前端收到 401 自动静默刷新一次，失败则跳登录页并保留原地址 |
| FR-AUTH-09 | 口令找回 | 无自助通道，由超管在「用户管理 → 重置口令」生成新口令交付 |

### 5.2 用户管理与数据隔离（USER）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-USER-01 | 用户即空间 | 平台只有用户一种账号形态，无租户/组织层级 |
| FR-USER-02 | 自动隔离 | 业务表带 `user_id`，登记到 `storyforge.data-permission.managed-tables` 后由数据权限插件自动追加过滤条件 |
| FR-USER-03 | 二次校验 | 按 ID 读写时再校验归属，越权统一返回「资源不存在」，不暴露存在性 |
| FR-USER-04 | 超管代建账号 | 用户名（唯一）、昵称、初始口令、角色（USER / SUPER_ADMIN）、备注；新用户首登强制改密 |
| FR-USER-05 | 用户列表 | 分页，支持用户名/昵称关键字、角色、状态、是否含已删除筛选 |
| FR-USER-06 | 编辑用户 | 可改昵称、角色、备注 |
| FR-USER-07 | 启停用户 | 停用后该用户令牌立即失效；启用后恢复 |
| FR-USER-08 | 重置口令 | 生成新口令，账号下次登录强制改密 |
| FR-USER-09 | 删除与恢复 | 逻辑删除，保留 30 天，期间可恢复；用户名被已删除账号占用时不可重复建号 |
| FR-USER-10 | 自我保护 | 不可停用/删除/重置自己；不可把系统最后一个启用的超管停用或降级 |

### 5.3 设置中心（SET）

设置中心是用户的统一配置入口，主导航包含「AI 接口管理」「联网搜索」「提示词模板」三个分区。

#### 5.3.1 AI 接口（SET-AI）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-SET-AI-01 | 多端点管理 | 一个用户可配多个端点：名称（用户内唯一）、baseUrl、apiKey、默认模型、超时、温度、max_tokens、top_p、附加请求头、启用状态 |
| FR-SET-AI-02 | 接口类型 | TEXT 文本 / IMAGE 图像；两类各自有独立默认端点；图像接口记录尺寸与平台类型 |
| FR-SET-AI-03 | 平台预填 | 新增图像接口时按平台预填地址、模型与尺寸（硅基流动 / OpenAI 兼容 / 火山方舟 / 智谱 / 阿里云百炼 / 魔搭） |
| FR-SET-AI-04 | 密钥保护 | API Key 以 AES-256-GCM 加密入库（`v1:base64(iv|ct)`），列表只回显掩码，编辑留空表示保留原密钥 |
| FR-SET-AI-05 | 连通性测试 | 文本接口发最小 chat 请求，返回 `{ok, latencyMs, model, reply, totalTokens, error}`；测试不计费入库 |
| FR-SET-AI-06 | 模型拉取 | 调用 `{baseUrl}/models` 获取模型列表并缓存；支持手工填模型名 |

| FR-NOVEL-129 | 每章质检 | 写完立即分析：大纲贴合度 <90 分则重新生成，最多 3 次，仍不达标取**评分最高**那版落库；**重写时把上一版「漏掉的剧情点」与「修改建议」写进提示词**，避免同一提示词重发导致分数不动；分析因前置章节未分析而跑不成时标为「分析不可用」并记日志，**不当作达标**；AI 率 <80 分则自动改写并覆盖本章（每章最多改写 1 次） |
| FR-NOVEL-130 | 周期体检 | 每写满 10 章体检一次（可选择是否跑 AI 深检）；硬伤（P0）数**超过**配置阈值即暂停任务并写明原因，需人工介入后才能继续 |
| FR-NOVEL-131 | 完结判定 | 「写满指定章数」达标即标记已完成；「直到完结」在累计字数进入预计完结字数前 1 万字时做**一次**收尾评估：剩余 ≤12 章 → 追加结局向总纲并 12 章内收束；剩余 >12 章 → 跳过收尾继续按原计划推进；剩余字数已不足 1 万字 → 不干预自然写完。收尾评估只触发一次 |
| FR-NOVEL-132 | 失败与熔断 | 单次 AI 调用失败原地重试 2 次（共 3 次尝试）；仍失败则结束本轮（已写好的章节保留），下个周期继续；**连续 3 个周期失败**则暂停任务 |
| FR-NOVEL-133 | 只读锁 | 任务启用且状态为「等待触发 / 正在生成」时，该书全部写操作被拒绝（`40073`）：基本信息、设定、章节、大纲、总纲、人物、势力、物品、事件、卷、AI 生成、导入；查询、导出、体检列表不受影响 |
| FR-NOVEL-134 | 显著提醒 | 工作台顶部常驻横幅提示「本书正在自动生成中」，并提供「前往自动写书」入口；编辑区（含弹窗提交按钮）整块禁用；停止任务后横幅消失、编辑立即恢复 |
| FR-NOVEL-135 | 立即执行与流水 | 可手动触发一轮；执行流水保留最近 50 轮，记录起止时间、结果、本轮成章数、补大纲 / 补总纲数、体检硬伤数、说明（包含本轮关闭了哪条总纲、当前在推哪条） |
| FR-NOVEL-136 | 自动写书的版本来源 | 自动写出的正文历史版本来源记为 `AUTO_WRITE`（列表显示「自动写书」），与手工、连写、流式生成区分 |
| FR-NOVEL-137 | 总纲状态与预计大纲数 | 总纲带推进状态（`PENDING` 未开始 / `RUNNING` 进行中 / `DONE` 已完成）与「预计大纲数量」。预计数量由模型规划时给出，**只作参考不是上限**：实际排多少条由故事需要决定，可以多于也可以少于它；该值不参与「这条总纲是否讲完」的判定 |
| FR-NOVEL-138 | 创作进度查看 | 「自动写书」页提供「创作进度」区：按序号列出全部总纲，显示状态、实际大纲数 / 预计大纲数；每条总纲可点「查看」打开抽屉，看到该总纲全文与其下全部章节大纲（章号、标题、摘要、已写 / 待写字数）。不看任务状态也能用（未启用自动写书时同样可查） |
| FR-NOVEL-139 | 总纲 / 大纲只读查看 | 「总纲」页每条总纲、「大纲」页每一章都有「查看」按钮（与「编辑」并列）：总纲抽屉显示状态、实际 / 预计大纲数、更新时间、全文，以及归属它的章节大纲（章号、标题、摘要、出场人物与事件、已写 / 待写）；章节抽屉显示状态、所属卷、关联总纲、更新时间、摘要、出场人物与事件、正文全文。抽屉纯只读——内部无任何输入框与保存按钮，要改仍须点「编辑」 |

### 5.8 整本导入（IMP）

把「只剩正文」的成稿导入成一本可续写的书：原文按章完整落库，AI 逆推出这本书自己的档案。与拆书改编的区别是拆书读完即弃原文、产出改编大纲，导入一个字都不丢。

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-IMP-01 | 上传解析 | 上传 txt/md（≥1000 汉字、≤500 万汉字），自动识别 UTF-8 / GB18030；按「第 X 卷」「第 X 章 / 第 X 节 / Chapter N」切卷切章；识别不到章节时按 2000 字在段落边界硬切并补「第 N 章」；正文前的短前言收成「序章」；单本上限 3000 章 |
| FR-IMP-02 | 原文完整入库 | 建书 + 卷 + 章节正文在一个事务内完成，`t_chapter.content` 存原文（只清洗换行与盗版广告行），字数按汉字统计；书名同一用户内唯一，撞名自动加「（2）」；书状态置 `WRITING` |
| FR-IMP-03 | 逆推设定 | 分段通读全书（单段 9000 汉字、最多 12 段，超长按头/中/尾抽样）得到事实清单，再归纳书名、题材、标签、简介、世界观、背景、核心冲突、核心看点、文风；五类写入设定文档，同时回写小说基础信息 |
| FR-IMP-04 | 逆推人物与势力 | 人物档案含身份、性别、年龄描述、角色定位、首次出场章、所属势力、性格、动机、经历；关系类型映射到既有枚举；势力含类别、活动范围、说明与成员。人名、组织名严格沿用原文写法 |
| FR-IMP-05 | 逆推物品 | 只收推动过剧情的物品，含类别、持有者、来历、作用与当前状态 |
| FR-IMP-06 | 逆推总纲与逐章大纲 | 一条总纲（一句话主线、主线推进、分幕、结局走向、未收束伏笔）写入 `t_master_outline`（`RUNNING`），全部章节挂到该总纲下；逐章回填 `summary`（每批 12 章） |
| FR-IMP-07 | 断点、重试与并发 | 八步流水线逐段回写百分比与阶段；AI 阶段失败不影响已入库正文，可「继续分析」只重跑逆推（不重建书、不重插章节）；同一用户同时只允许一个导入任务（`40086`）；服务重启把未完成任务标记失败 |

边界：文本过短 `40084`、过长 `40085`、非文本 `40083`、记录不存在 `40082`；非法 JSON 自动重试一次；原文入库失败整笔回滚，不留半本书。

## 6. 非功能需求（NFR）

### 6.1 性能与容量

| 编号 | 需求 |
|---|---|
| NFR-01 | 普通 CRUD 接口 P95 < 300ms（不含 AI 调用） |
| NFR-02 | 列表接口默认分页 20 条，单页上限 200 |
| NFR-03 | 单章正文（≤20KB 文本）加载与保存 < 500ms |
| NFR-04 | 不要求高并发：面向个人创作者与小规模用户，单实例部署即可，不按互联网高并发场景设计 |
| NFR-05 | 支撑单用户 50 本小说、单本 2000 章、总汉字 2000 万量级 |
| NFR-06 | AI 类接口前端超时 180s（普通接口 30s）；蓝图与拆书单段 5 分钟 |

### 6.2 安全

| 编号 | 需求 |
|---|---|
| NFR-07 | 口令 BCrypt（cost 10）存储；长度 ≥ 8 且含字母与数字 |
| NFR-08 | AI 与搜索 API Key 以 AES-256-GCM 加密入库，主密钥来自 `STORYFORGE_SECRET_KEY`，不入库、不落日志、上线后不可更换 |
| NFR-09 | 日志禁止出现密钥、令牌与正文全文 |
| NFR-10 | 令牌 access 30 分钟 / refresh 7 天，refresh 轮换；登出与轮换的 `jti` 落黑名单表 |
| NFR-11 | 限流：进程内令牌桶（单实例生效）——登录 10 次/分/IP；读 600 次/分/用户；写 120 次/分/用户；AI 生成类 30 次/分/用户 |
| NFR-12 | SQL 参数占位防注入；正文按纯文本渲染；无状态 JWT 天然免疫 CSRF |
| NFR-13 | 越权统一返回「资源不存在」，不泄露存在性 |
| NFR-14 | 停用用户每次请求校验状态，令牌立即失效 |

### 6.3 可用性与可维护性

| 编号 | 需求 |
|---|---|
| NFR-15 | 服务无状态（JWT），无 Redis/MQ/ES/MinIO 等外部中间件 |

## 10. 假设与约束

1. 用户自备 AI 服务与额度，平台不代付；输出质量取决于所选模型。
2. 平台只有用户一种账号形态，无组织/协作概念；每个用户的数据空间完全独立。
3. 账号仅能由超管开通，口令交付默认线下完成。
4. 联网搜索为可选增强，未配置或不可达时生成流程按无资料继续。
5. 章节分析、按分析修改、智能助手都依赖模型能力；平台保证流程正确、失败可见、可重试。
6. 平台不承担生成内容的合规与版权责任，需在界面提供提示。
7. 面向个人创作者与小规模用户，不要求高并发，因此采用进程内限流、进程内缓存与本地文件存储。
