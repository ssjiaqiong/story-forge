## 1. 支持矩阵

| profile | 数据库 | 版本下限 | 典型场景 | 实测版本 |
|---|---|---|---|---|
| 默认（不指定） | PostgreSQL | 12（推荐 16/18） | 服务器部署、多用户共用 | 18.3 / 16（容器） |
| `mysql` | MySQL / MariaDB | 8.0.13 / 10.2 | 已有 MySQL 运维体系 | 9.2.0 |
| `sqlite` | SQLite | 3.35 | 桌面单机版、本地演示 | 3.47.2（JDBC 内置） |

一次启动只使用一种数据库，切换仅靠 profile，不改代码、不重新编译。

```bash
# PostgreSQL（默认）
java -jar app.jar

# MySQL（库需提前创建）
SPRING_PROFILES_ACTIVE=mysql DB_HOST=127.0.0.1 DB_PORT=3306 DB_NAME=storyforge \
DB_USER=root DB_PASSWORD=xxx java -jar app.jar

# SQLite（文件不存在会自动创建）
SPRING_PROFILES_ACTIVE=sqlite SQLITE_PATH=./data/storyforge.db java -jar app.jar
```

## 2. 配置分层

```text
application.yml            公共配置 + PostgreSQL 默认数据源（被 profile 整体覆盖）
application-mysql.yml      MySQL 数据源 + MyBatis databaseId=mysql
application-sqlite.yml     SQLite 数据源（WAL、busy_timeout=10s、连接池 4）+ 时间 TypeHandler
application-dev.yml        本地开发（日志、SQL 打印）
```

关键项：

| 配置 | 说明 |
|---|---|
| `spring.flyway.locations` | 按 profile 指向 `db/migration/{postgresql,mysql,sqlite}` |
| `spring.flyway.baseline-version: 1` | 已有库接管用；历史表被重置后写入 BASELINE 并跳过 V1 |
| `spring.datasource.hikari.maximum-pool-size` | PG/MySQL 默认 10，SQLite 4 |
| `storyforge.storage.root` | 业务文件根，默认 `${storyforge.home:./data}/files` |
| `storyforge.cover.root` | 封面根，默认 `${storyforge.home:./data}/covers` |
| `storyforge.data-permission.managed-tables` | 参与自动隔离的表清单 |

## 3. DDL：三份基线，同源派生

```text
db/migration/
├── postgresql/V1__baseline.sql   ← 唯一事实来源（pg_dump --schema-only 导出终态）
├── mysql/V1__baseline.sql        ← 由脚本派生，禁止手工改
├── sqlite/V1__baseline.sql       ← 由脚本派生，禁止手工改
├── */V2__novel_constraint.sql    ← V2+ 三份手写（增量迁移），派生脚本不管
├── */V3__chapter_version.sql
├── */V5__consistency_issue.sql
├── */V6__volume.sql
├── */V7__auto_write.sql      ← t_novel.planned_words + t_auto_write_task + t_auto_write_run
└── */V8__agent_plan.sql    ← t_novel_agent_plan + t_novel_agent_plan_step（智能助手分步任务）
```

派生与校验：

```bash
node script/db/gen-baseline.mjs          # 改完 PG 基线后重新派生另两份
node script/db/gen-baseline.mjs --check  # 只校验三份是否同步（CI 用）
```

**变更规则**：

1. 结构变更只改 PostgreSQL 基线所表达的「目标结构」，但**不允许直接改 `V1__baseline.sql`**；
   新增 `V2__xxx.sql`、`V3__xxx.sql`……
2. 三份迁移目录必须同步新增同名文件。**`V1__baseline` 由派生脚本生成，`V2` 及以后的增量迁移三份手写**：
   PostgreSQL 用 `COMMENT ON COLUMN`、MySQL 用内联 `COMMENT`、SQLite 不写注释；其余差异照上表的语法转换要点翻译。
3. 禁止手工执行 DDL 改表，避免 Flyway 校验失败。

**语法转换要点**（脚本已处理）：

| PostgreSQL | MySQL | SQLite |
|---|---|---|
| `BIGINT` 自增/雪花 | `BIGINT` | `INTEGER` |
| `TEXT` / `VARCHAR(n)` | `VARCHAR(n)` / `LONGTEXT` | `TEXT` |
| `BOOLEAN` | `TINYINT(1)` | `INTEGER` |
| `NUMERIC` / `INT` | `DECIMAL` / `INT` | `NUMERIC` / `INTEGER` |
| 部分唯一索引 `WHERE deleted = 0` | 条件函数列 `((CASE WHEN deleted = 0 THEN 0 ELSE NULL END))` | 部分索引原生支持 |
| `DEFAULT now()` | 去掉默认（应用侧写入） | `(datetime('now','localtime'))` |

## 4. DML：方言纪律

Mapper XML 与 Java 中不出现任何数据库专有语法。

| 场景 | 写法 |
|---|---|
| 大小写不敏感匹配 | `LOWER(col) LIKE LOWER(CONCAT('%', #{kw}, '%'))`（三库语义一致） |
| 时间加减（一天/一月） | 在 Java 侧算好边界再传参，不用 `INTERVAL` / `DATE_ADD` |
| 取日期部分 | `<sql id="dateOf">` 片段按 `_databaseId` 分支（PG `CAST AS DATE` / MySQL `DATE()` / SQLite `substr(col,1,10)`） |
| 当前时间 | 一律应用侧写入（`AuditMetaObjectHandler` 或调用方传参） |
| 分页 | MyBatis-Plus 分页插件按 JDBC URL 自动识别方言，**不写死 `DbType`** |

`_databaseId` 由 `DatabaseDialectConfig` 注入，取值 `postgresql` / `mysql` / `sqlite`。

## 5. 运行时兼容层

| 组件 | 作用 |
|---|---|
| `DbDialect` / `DbDialectProvider` | 启动时探测并校验数据库版本（PG ≥ 12 / MySQL ≥ 8.0.13 / SQLite ≥ 3.35），未登记的方言直接失败 |
| `DatabaseDialectConfig` | 提供 `databaseId` 与各库的 SQL 片段映射 |
| `SqliteLocalDateTimeTypeHandler` | SQLite 时间列 TEXT ↔ `LocalDateTime`，格式 `yyyy-MM-dd HH:mm:ss.SSS` |
| `MybatisPlusConfig` | 数据权限 → 分页 → 乐观锁 → 防全表更新，顺序固定 |

> 新增方言必须在 `DbDialect` 枚举登记，否则启动失败——静默回退会让 SQL 打到错误的库上。

## 7. 部署形态

### 7.1 本地开发

```bash
# 后端（Flyway 自动建表 + 初始超管）
mvn -DskipTests clean package
java -jar target/app.jar

# 前端（dev server，/api 代理到 8080）
cd web && npm install && npm run dev
```

前端改动必须构建并同步到 jar 的静态目录（pom 不含前端插件）：

```bash
cd web && npm run build && cp -r dist/. ../src/main/resources/static/
```

### 7.2 单机容器

```bash
cd docker
cp .env.example .env      # 至少改 STORYFORGE_JWT_SECRET / STORYFORGE_SECRET_KEY / DB_PASSWORD
docker compose up -d --build
curl -f http://127.0.0.1:8080/actuator/health
```

### 7.3 远程服务器（SSH → Compose）

配置 `script/deploy/server.env`（模板 `server.env.example`）：

| 变量 | 说明 |
|---|---|
| `HOST` / `USER` / `SSH_PORT` | 服务器地址与登录方式 |
| `KEY` | SSH 私钥路径（相对 `script/deploy/`） |
| `REMOTE_DIR` | 远端部署目录，默认 `/opt/storyforge` |
| `APP_PORT` | 对外端口，默认 8080 |
| `JAVA_OPTS` | 容器内 JVM 参数（2C2G 建议 `-Xms128m -Xmx640m`） |
| `REGISTRY` / `IMAGE_NAME` / `IMAGE_TAG` / `REGISTRY_USER` | 镜像仓库信息（密码不落盘） |

常用命令：

```bash
./script/deploy/deploy.sh                # 拉镜像 → 启动 → 健康检查（默认，不编译）
./script/deploy/deploy.sh --image ccr.ccs.tencentyun.com/jiaqiong/story-forge:v1.0.1
./script/deploy/deploy.sh --from-source  # 从源码构建（需 JDK/Maven/Node，离线兜底）
./script/deploy/deploy.sh status         # 容器状态 + 健康 + 磁盘/内存
./script/deploy/deploy.sh logs 300       # 应用日志
./script/deploy/deploy.sh restart        # 重启应用容器
./script/deploy/deploy.sh stop           # 停止（保留数据）
./script/deploy/deploy.sh psql           # 进 PostgreSQL
```

行为约定：

- **远端不跑 Maven/Node**：本地打好 jar 上传，远端 Dockerfile 只装 jar，构建几秒完成。
- **`.env` 只首部署生成**，再次部署不覆盖；主密钥变更会导致已存 API Key 密文无法解密。
- 2C2G 内存：JVM 640m + PG `shared_buffers=128MB`，不要随意调大。
- 公网不通先看 `status` 的 health：health=UP 说明是云控制台防火墙未放行端口。

### 7.4 镜像与 TCR

```bash
./script/deploy/build.sh                 # 打 jar → 构建镜像 → 推送 ${IMAGE_TAG}
./script/deploy/build.sh --skip-jar      # 复用 target/app.jar
./script/deploy/build.sh --tag v1.0.1    # 指定标签
./script/deploy/build.sh --also-latest   # 额外推 latest
./script/deploy/build.sh --no-push       # 只构建
./script/deploy/build.sh --local         # 在本机 Docker 构建（默认在服务器）
./script/deploy/build.sh login           # 登录 TCR
./script/build.sh --image                # 打包 + 推镜像一条命令
```

**重要**：TCR 对较大层使用 `docker push` 容易出现 `net/http: timeout awaiting response headers`，且失败后 `docker image inspect .RepoDigests` 仍会显示 digest（假成功）。因此：

- 推送优先 `skopeo copy --dest-authfile ... docker-daemon:<ref> docker://<ref>`（分块上传 + 重试）；
- 服务器安装：`dnf install -y skopeo`；
- 校验以仓库侧为准：`skopeo inspect --authfile ... docker://<ref>`；
- `daemon.json` 增加 `"max-concurrent-uploads": 1` 缓解大层超时。

### 7.5 Nginx HTTPS 网关

模板：`script/deploy/remote/nginx-storyforge.conf`，部署到 `/etc/nginx/conf.d/`。

```nginx
server {                      # 80 → 301
    listen 80;
    server_name www.example.com example.com;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    http2 on;
    server_name www.example.com example.com;
    ssl_certificate     /etc/nginx/ssl/bundle.crt;
    ssl_certificate_key /etc/nginx/ssl/private.key;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_buffering off;               # 长耗时生成请求不被缓冲
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

要点：

- `proxy_buffering off` 必须开，否则长耗时生成请求会被网关攒住。
- 证书文件权限：key `600`、crt `644`；目录 `/etc/nginx/ssl`。
- 默认**不开 HSTS**：证书短期（约 3 个月）续期失败时不会把浏览器锁死。
- 修改后必须 `nginx -t` 校验再 `systemctl reload nginx`。
- 证书到期前替换文件并 reload；`systemctl enable nginx` 保证开机自启。

### 7.6 Windows 桌面版

```powershell
.\script\gen-icon.ps1        # 生成图标（首次或改图后）
.\script\package-win.ps1     # 前端 → static → Maven → jpackage
.\script\package-win.ps1 -SkipBuild   # 复用 target\app.jar
```

运行行为：

- 双击 exe → 选端口（8080 起，占用则顺延至 8089）→ 起服务 → 打开浏览器。
- 再双击不会起第二个进程，而是打开已运行实例（读 `data/.instance.port`）。
- 默认账号 `admin / Admin@123456`，首登强制改密。
- 重置数据 = 关闭程序后删除 `data/` 目录。

## 8. 运维手册

### 8.1 日常检查

```bash
./script/deploy/deploy.sh status
ssh root@<host> "cd /opt/storyforge && docker compose ps"
curl -fsS https://<domain>/actuator/health
```

| 现象 | 判断 | 处理 |
|---|---|---|
| health 非 200 | 应用未起或数据库不可用 | `deploy.sh logs 300` 看异常；`psql` 验证连通 |
| 容器反复 Restarting | 常见为 Flyway 迁移失败 | 看日志中的 SQLState；修复脚本或重置历史表 |
| 公网不通但容器 healthy | 云防火墙未放行 | 控制台放行 TCP 端口 |
| 页面 502 | Nginx 反代目标错误 / 应用未监听 | `ss -tlnp \| grep 8080`，检查 upstream 端口 |
| 上传大文件 413 | Nginx `client_max_body_size` 过小 | 调大并 reload |

### 8.2 备份与恢复

| 对象 | 方式 |
|---|---|
| 数据库 | `docker compose exec -T postgres pg_dump -U storyforge -d storyforge \| gzip > backup.sql.gz` |
| 封面与文件 | 打包 `/opt/storyforge/data/{covers,files}` |
| 单本小说 | 站内「导出 JSON」（含封面 Base64），可跨库/跨站点迁移 |
| 桌面版 | 关闭程序后复制 `data/` 目录 |

**恢复注意**：PostgreSQL 18 的 `pg_dump` 会输出 `\restrict` / `SET transaction_timeout`，导入 PG16 会报 `42704`。恢复前剔除这些行。

### 8.3 升级发布

```bash
# 标准流程（推荐）：先推镜像，再拉镜像部署
./script/deploy/build.sh --tag v1.0.1
./script/deploy/deploy.sh --image ccr.ccs.tencentyun.com/jiaqiong/story-forge:v1.0.1

# 或者改完 remote/docker-compose.yml 的默认 image 后直接跑
./script/deploy/deploy.sh

# 兜底：源码构建部署（需 JDK/Maven/Node，不推镜像）
./script/build.sh
./script/deploy/deploy.sh --from-source --skip-build
```

升级只替换应用容器，`data/` 卷与 `.env` 不动；Flyway 在启动时自动执行新增迁移。

### 8.4 回滚

```bash
# 回滚 = 换回上一个镜像标签再起一次（无需重新构建）
./script/deploy/deploy.sh --image ccr.ccs.tencentyun.com/jiaqiong/story-forge:<上一版本>
```

⚠️ 若新版本执行过不兼容的迁移，回滚前需评估：Flyway 不自动回退，必要时用备份恢复数据库。

### 8.5 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `Flyway validate failed` | 手改过迁移文件或三份基线不同步 | `node script/db/gen-baseline.mjs --check`；恢复文件一致性 |
| `baselined schema with version: 1` 后启动 | 正常接管已有库 | 无需处理 |
| 已存 API Key 解不开 | `STORYFORGE_SECRET_KEY` 被更换 | 恢复原主密钥；密钥不可更换 |
| 封面 404/丢失 | 文件卷未挂载或路径不对 | 检查 `STORYFORGE_COVER_ROOT` 与卷映射 |
| TCR 推送超时 | 大层上传 | 用 skopeo；确认 `max-concurrent-uploads: 1` |
| 桌面版打不开 / 端口冲突 | 已有实例或端口占用 | 查看 `data/.instance.port`；关闭残留进程 |
| SQLite `database is locked` | 并发写 | 降低并发；确认连接池 4 与 `busy_timeout=10000` |
| 自动写书到点不跑 | 任务已 `PAUSED`/`STOPPED`/`COMPLETED`，或 cron 非法 | `GET /api/auto-write/novels/{novelId}` 看 `status` 与 `nextRunAt`；`PAUSED` 需处理后重新启用 |
| 书籍被锁、按钮全灰 | 自动写书启用期间该书只读（`enabled=1` 且 `IDLE/RUNNING` 即锁，正常行为） | 页面「自动写书 → 停止并解锁编辑」，或 `PUT /api/auto-write/{id}/enabled?enabled=false` |
| 自动写书连续失败熔断 | 连续 3 个周期 AI 调用失败 | 看 `t_auto_write_run.message` 与 AI 端点/密钥；修复后在页面重新启用（自动清零失败计数） |
| 自动写书被体检拦停 | 体检 P0 数超过配置阈值 | 处理 `t_consistency_issue` 中该轮问题，再重新启用 |

### 8.6 安全清单（上线前）

- [ ] `STORYFORGE_JWT_SECRET` ≥ 32 字节随机值
- [ ] `STORYFORGE_SECRET_KEY` 随机值，已离线备份且**永不更换**
- [ ] 数据库口令非默认值，`.env` 权限 600
- [ ] 初始 admin 口令已修改（修改后 `.env` 中的初始值失效）
- [ ] 仅暴露 443（必要时 80），8080 不直接对外
- [ ] 证书到期时间已记录，续期流程已确认
- [ ] `data/` 与数据库有定期备份
