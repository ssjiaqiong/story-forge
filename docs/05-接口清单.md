# 05 · 接口清单

> 从 [`../README.md`](../README.md) 拆出：README 只保留快速开始与运行相关的内容，接口明细统一放这里。
> 接口的权威来源始终是代码与 `/v3/api-docs`；本文只是给人读的分类索引，改动接口时请同步这一页。

统一响应体：`{ "code": 0, "message": "ok", "data": {}, "traceId": "..." }`（`code=0` 为成功）。

## AI 接口管理 `/api/ai-configs`（登录用户，按用户隔离）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `` | 列表，默认端点排在最前；API Key 只返回掩码 |
| GET | `/{id}` | 详情（含最近一次拉取的模型列表缓存） |
| POST | `` | 新增：`name/baseUrl/apiKey/defaultModel` + 可选 `kind`（TEXT/IMAGE，默认 TEXT）、`provider`、`imageSize`、`timeoutMs/temperature/maxTokens/topP/extraHeaders/enabled/isDefault` |
| PUT | `/{id}` | 编辑，字段为 `null` 不修改；`apiKey` 留空表示保留原密钥 |
| DELETE | `/{id}` | 删除（被场景绑定时返回 `40010`） |
| PUT | `/{id}/default` | 设为默认端点（停用的接口返回 `40009`） |
| PUT | `/{id}/status` | 启用 / 停用；停用默认端点会同时取消默认标记 |
| POST | `/{id}/test` | 连通性测试，返回 `{ok, latencyMs, model, reply, totalTokens, error}` |
| GET | `/{id}/models` | 拉取 `{baseUrl}/models` 并缓存 |
| GET | `/export?includeApiKey=true` | **导出全部接口配置**为 JSON 附件（`storyforge-ai-config-export` v1）；含明文密钥时文件等同于凭据 |
| POST | `/import` | **导入接口配置**：逐条校验、单条失败只跳过该条；重名自动追加「（2）」；密钥用本实例主密钥重新加密；不抢占已有默认端点 |

约定：`baseUrl` 需包含版本段（如 `https://api.openai.com/v1`），系统在其后追加 `/chat/completions` 与 `/models`。
API Key 以 **AES-256-GCM** 加密入库（`v1:base64(iv|ct)`），主密钥来自 `STORYFORGE_SECRET_KEY`。

导入导出的边界：

- 搬运 `name/kind/provider/imageSize/baseUrl/apiKey/defaultModel/modelList/timeoutMs/temperature/maxTokens/topP/extraHeaders/enabled/isDefault/remark`；
- **不搬运** `id`、创建/更新时间、最近测试结果（都是本实例的运行痕迹）；
- 密钥密文绑定站点主密钥，跨站点无法解密，因此导出的是解密后的明文，导入时用目标站点密钥重新加密；
- `includeApiKey=false` 导出的包不含密钥，导入后这些接口显示「未配置密钥」，需编辑补填；
- 单次导入上限 200 条，限流 10 次/分钟。

## 章节分析与按分析修改 `/api/bookshelf`（登录用户，按用户隔离）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/chapters/{id}/analysis` | 分析本章（按章节顺序校验）；同步新人物、变更履历、事件状态 |
| POST | `/chapters/{id}/revise` | **按分析修改**：传入勾选的问题、自定义要求、修改幅度与目标字数，返回原文 + 新稿，**不落库** |
| GET | `/novels/{id}/analysis-overview` | 分析面板列表：每章最近一次结果与状态 |
| GET | `/chapters/{id}/analyses` | 本章分析历史（最近 20 次） |
| GET | `/analyses/{id}` | 报告详情 |
| GET | `/novels/{id}/change-histories` | 要素变更履历（可按类型 / 实体过滤） |

`revise` 入参：`analysisId`（可空）、`items[]{type,text,detail}`（type ∈ `OUTLINE_MISS`/`OUTLINE_SUGGESTION`/`AI_SIGNAL`/`AI_EXAMPLE`/`LENGTH`，最多 24 条）、`instruction`（≤2000 字）、`intensity`（`LIGHT`/`MEDIUM`/`HEAVY`）、`targetWords`。
返回：`originalContent`、`revisedContent`、`notes[]`（AI 自述改动要点）、`wordCountBefore/After`、`model`、`latencyMs`。
未分析过的章节返回 `40051`，生成不出可用新稿返回 `40052`；保存仍走 `PUT /chapters/{id}`，保存后由前端触发一次重新分析。
本章是「已完成」（`DONE`）时，前端先弹确认框，作者点「覆盖保存」才带 `overwriteDone: true` 重发——服务端只放行这一次覆盖，章节状态不变、覆盖前正文照旧存历史版本；不带该字段仍按锁定返回 `40061`。

## 事实层（章节事实 / 伏笔）`/api/bookshelf`（登录用户，按用户隔离）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/chapters/{chapterId}/facts` | 本章事实：事实摘要 + 来源 + 本章新埋 / 回收的伏笔 + 角色状态 |
| PUT | `/chapters/{chapterId}/fact-summary` | 手改事实摘要（`{ "factSummary": "..." }`），成功后 `factSource` 变 `MANUAL`，此后重新分析不再覆盖 |
| GET | `/novels/{novelId}/foreshadows?status=OPEN` | 伏笔台账；`status` 可空（全部）/`OPEN`/`PAID`/`DROPPED` |
| POST | `/novels/{novelId}/foreshadows` | 新增伏笔 |
| PUT | `/foreshadows/{id}` | 修改伏笔（标题 / 内容 / 埋设章 / 计划回收章 / 状态 / 备注），改 `status=PAID` 时写回收章 |
| DELETE | `/foreshadows/{id}` | 删除伏笔（逻辑删） |

`GET /facts` 返回：`chapterId`、`chapterNo`、`chapterTitle`、`factSummary`（为空表示还没分析）、`factSource`（`AI`/`MANUAL`/`BACKFILL`）、
`planted[]` 与 `paid[]`（伏笔，同下）、`states[]`（`characterId`、`characterName`、`chapterNo`、`location`、`condition`、`mood`、`knowsAdded[]`、`knowsHidden[]`）。

伏笔字段：`id`、`title`、`content`、`plantedChapterNo`、`plannedPayoffChapter`、`status`（+ 中文 `statusLabel`）、`payoffChapterNo`、
`overdue`、`overdueChapters`、`note`。`overdue` 是**实时算**的（`OPEN` 且已超过计划回收章，未填计划章按埋设章 + 30），不落库。
写操作（`PUT fact-summary`、伏笔增删改）在自动写书启用期返回 `40073`。

## 整本 TXT 导入 `/api/bookshelf/import`（登录用户，按用户隔离）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tasks` | **上传并启动导入**（multipart）：`file`（必需，`.txt`/`.md`，1000~500 万汉字）+ `title`、`penName`（可空，缺省取文件名）。立即返回任务（`RUNNING`），正文入库后再跑 AI 逆推 |
| GET | `/tasks/{taskId}` | 任务进度：`status`（`RUNNING`/`SUCCESS`/`FAILED`）、`percent`、`stepNo`、`stepLabel`、`sourceChars`、`chapterCount`、`volumeCount`、`importedChapters`、`novelId`、`errorMessage`、`summary` |
| POST | `/tasks/{taskId}/retry` | **继续分析**：只重跑 AI 逆推（通读 → 设定 → 人物 → 物品 → 总纲 → 章纲），**不重建书、不重插章节**；正文入库失败的任务不可重试 |
| GET | `/tasks` | 导入记录分页（`page`/`size`） |
| DELETE | `/tasks/{taskId}` | 删除导入记录（**不动已生成的小说**） |

`POST /tasks` 只同步做「解码 → 清洗 → 切卷切章 → 校验字数与章数」，随即返回任务；建书与逐章落库在后台线程内
一个事务完成，之后跑 AI 逆推。八步流水线（入库 / 通读 / 设定 / 人物 / 物品 / 总纲 / 章纲 / 收尾）逐步回写
`percent` 与 `stepLabel`，前端轮询 `GET /tasks/{taskId}` 即可。
同一用户同时只允许一个导入任务（`40086`）；文本过短 `40084`、过长 `40085`、非文本 `40083`、记录不存在 `40082`。
AI 失败不影响已入库正文，书照样能打开能续写。
